# AGENTS.md

The free core: the repository / build-cache server modules consumed by downstream editions. This file is the authoritative contributor and agent guidance for the repository.

## Build & test

- `java build/jenesis/Project.java` resolves, compiles, and tests every module. **Requires JDK 25** (the sources use module-import declarations and unnamed variables). The build tool is the `.jenesis/upstream` git submodule pinned to a raphw/jenesis commit (`build/jenesis` is a symlink into it) — run `git submodule update --init` once after cloning.
- Fast iteration — build one module's subgraph with a `+` selector: `+source+<path>` or `+test+<path>` (e.g. `+test+store+s3`; a nested `store/s3` is written `+store+s3`, and `/<step>` drills into a step). `+` selectors are *lenient* — a wrong one silently matches nothing, so confirm your module shows an `[EXECUTED]` line.
- `-Djenesis.*` system properties go **before** the `Project.java` path; bare selectors go **after** it.
- `java build/jenesis/Project.java help` documents every selector and `-D` flag (`pin` regenerates the `@jenesis.pin` version/checksum lines; `export` produces the deliverable repository).

## Local gotchas (a red here is often the environment, not a regression)

- **Docker is the only host tool the suite needs** (besides JDK 25). Ecosystem clients run from pinned images through `ToolContainer`, never from the host `PATH` — Maven from `maven:3.9.9-eclipse-temurin-21`, Helm from `alpine/helm:3.16.3` — so there is no `mvn` or `helm` to install. The backing services are containers too: MinIO (`s3`/`gcs`), Azurite (`azure`), Nexus, Artifactory OSS and `selenium/standalone-chrome`. Only the `docker` CLI itself is executed on the host, by the suites that drive a real client against the registry (`OciDockerTest`, `OciProxyTest`) and by the Artifactory boot.
- Container-backed tests **self-skip without Docker**; the strict CI lane (`-Djenesis.project.properties=ci`) makes them *fail* instead. A full local run is therefore `java -Djenesis.project.properties=ci build/jenesis/Project.java` — a green run there is a run that really executed every tagged suite.
- A few tests need a **UTF-8 locale**: `MavenMetadataTest` publishes non-ASCII versions (`naïve`, `café`) into a filesystem store, where they become real filenames and so depend on `sun.jnu.encoding`. Set `LANG=C.UTF-8` if your locale is not already UTF-8.

## Engineering principles

These rules are the pass/fail checklist. Run every applicable rule by eye over each diff and fix or explicitly flag failures before the change lands. This free core is the shared base downstream editions reuse, so keep its seams clean and never fork its mechanism downstream.

- **Stream, never buffer (§1).** No whole-blob read (`readAllBytes`/`toByteArray`) of an *artifact* on any upload/download/proxy path — only a small index/metadata blob may be fully materialised. A hosted publish is store-then-gate (hash-on-write into CAS, gate a descriptor, not a `byte[]`); proxy uses the streaming `download` path; `HEAD` answers from metadata; heap stays bounded under a >2 GiB upload.
- **Thin core, pluggable SPI (§2).** A `format/*` / `compliance/*` module requires only its SPI, never a peer plugin or the server; the server `uses` SPIs and `requires` no concrete plugin. New capabilities are `ServiceLoader`-discovered and SPI-named — not a core edit. No focal class enumerates plugged concepts by hand (formats, inspectors, feeds, hold kinds, settings, screens fan out through their SPI). SPI *contract* modules stay `java.base`-light; the heavy deps ride the impl/bundle. Controllers and views stay thin; domain logic stays in domain modules. Shared mechanism lives here and is extended through default-no-op SPI hooks when a downstream edition needs a missing seam — never copied into a downstream controller, pipeline, or edge. No new database — all durable state is `ArtifactStore` objects.
- **Optional, discovered, graceful (§3).** An optional module's absence never prevents boot: its endpoint returns `501`, its UI says "not installed", and resolution uses an SPI `NONE`/empty sentinel rather than `null` or an exception. Installed capabilities advertise themselves through `/api/capabilities`. New runtime knobs are documented `SettingsContributor` settings, not hardcoded constants or redeploy-only environment variables. Observed operations use the shared `Observations.observe(...)` wrapper; `jenesis.*` meters use lowercase dotted names and low-cardinality tags.
- **Persist only through the store; converge idempotently (§4).** All persistence goes through the store SPI (`ArtifactStore` / `CacheStorage`) — no raw `File`/`Path`, no direct cloud SDK outside a provider module. Everything durable is a store object: CAS for immutable content, `writeVersioned` (compare-and-set, check the result and retry on conflict) for mutable pointers, a `Lease` for single-writer sweeps. Every derived surface either converges after a crash through a `Lease`-guarded idempotent repair pass, or its javadoc states it is best-effort and why. Hosted publish is idempotent: write the content-addressed blob, link it with CAS, fail loudly before commit, and contain only explicitly after-commit observers. A lost best-effort write may only over-serve or over-count; it must never hide a served artifact or a hold.
- **Self-healing — converge even when added late (§5).** A capability switched on *late*, over a store that already holds artifacts from before the plugin existed, back-fills its derived state from the durable store on first activation (same `Lease`-guarded pass) and re-checks on each start — adopting a plugin is a config flip, never a re-import or manual migration. Where it genuinely cannot back-fill it degrades gracefully and says so through its `NONE`/empty sentinel or health surface; it **never serves a silently-incomplete view as if it were whole**. Open-ended kinds (formats, feeds, hold kinds) survive a plugin added at any point in the product's life.
- **Tenant-scoped, gated, audited (§6).** Every HTTP surface derives its tenant from the key, uses traversal-guarded tenant storage, and prevents cross-tenant reads. Plugin state is tenant-scoped by default; only deployment-global auth data under `auth/` and superadmin configuration under `config/` may be shared. Console operations use the selected tenant, but single-tenant use shows no tenancy chrome. Gate each operation with the correct `<surface>:<verb>` authorization; audit every privileged mutation.
- **Read-first performance (§7).** The reader pays for nothing a writer or sweep could pre-do; precompute/cache/roll-up on write or in a background sweep. Prefix listing and direct key lookups, never full scans. Generated-on-read output (POM, `maven-metadata.xml`, indexes) is cacheable and ETag-revalidatable.
- **Prefer libraries over hand-rolling (§8).** Reach for a maintained, permissively-licensed library for parsers/codecs/compression/crypto/hashing/encoding/HTTP first. Hand-roll only when nothing fits the module path / native-image / licence — then keep it minimal, say why in the code, and pin it to the reference output with a test.
- **Fail fast; make errors visible (§9).** A capability an operator *explicitly selected* that cannot be honoured (module absent, name misspelled, required config unset) throws at resolution/startup — never a silent fallback (the store is the exemplar: `store=s3` with the s3 module off must not boot against the local filesystem). A config error names what was selected and what is missing. No swallowed failure on a correctness-bearing path: an exception whose loss would change what is served, held or counted is logged/countered/surfaced, never caught into a silent default.
- **Reads render, writes refresh (§10).** A GET renders only what is durably stored — no external fetch/scan/write on the read path, and the view stands when the source is down. Refreshing feeds/upstreams/scanners is an explicit, idempotent, write-role action (button or `refresh=true`), beside the scheduled sweeps. Every derived/externally-sourced view shows its last fetch/scan instant so an empty panel is never ambiguous between "clean" and "never scanned". A caller lacking the write role sees no refresh control but still sees the staleness.
- **Prefer immutability; scope mutation locally (§11).** Types are immutable by default — `final` fields, `record`s and immutable value types, unmodifiable collections both handed out and defensively taken in. A method returns a fresh value rather than mutating an argument or a shared field; there are no setters churning a live object and no mutable static state. Mutability is confined to **method-local** scope — a loop accumulator, a `StringBuilder`, a builder assembled and then frozen before it escapes. A shared object a reader holds cannot then change under it mid-view (§10), and reading shared state needs no lock.
- **Configuration = env-var→Spring-Boot or UI-controlled (§12).** Runtime config reaches the app by exactly two paths: env vars bound into Spring Boot at startup (deploy-time infra — store, ports, credentials, `trustedProxies`), or `SettingsContributor`-declared UI settings the app writes through the store (runtime dials, editable in the console). No stranded constant (a `config().apply(...)` key declared by no contributor and bound to no env var), no hand-edited store/S3 config object. A structural test fails the build on a read key that is neither declared nor on the env-var bootstrap allowlist.
- **Cross-format parity (§13).** Formats treat like concerns alike: a guard/cap/behaviour one format applies to a shared concern (archive-inflation caps, path-traversal guards, withhold-on-enumeration, proxy integrity verification, streaming) is applied by EVERY format with that concern. A new format arrives at parity with its peers; a fix to one format's guard is retrofitted to all peers in the *same* change. Undocumented divergence on a shared concern is a bug.
- **Independent naming (§14).** Names are created from root; no type/module/endpoint/setting leans on a competing product's terminology for one of our own concepts — a competitor's name appears only for a genuine explicit integration (`NexusSource` imports from Nexus), never as a borrowed label for our own mechanism.
- **Adherence is checked.** Mechanically-checkable principles carry a `*PrincipleTest` or `*GuardTest` build guard. Semantic rules (§13/§14 and §2's shared-mechanism/plug-in rule) are verified by a periodic principle checkup. A checkup reports concrete deviations; each fix carries the §13 retrofit to every peer.
- **No backwards-compatibility shims.** Defaulting-secure and clean cutovers are preferred over compat layers; there is no requirement to preserve an old wire/format/behaviour across a change.
- **Flag, don't force.** If a feature can only be met by fighting these gates, mark it flagged for a human decision rather than hand-rolling a workaround that fights them.
